今回の手引きは、完成記事から学んでこちらの作業に落としたもの。四人が同じ工程で書いているという記録ではない。

## デザインで確かめたことと、残る確認

本文・ナビゲーションの抽出から、どんな入口・カテゴリ・著者欄・関連記事・販売リンクがあるかは確認できた。ただしテキストの抽出順は、実画面の左右・上下の配置を完全に表さない。

ブラウザーからは、とっとこ、井ノ上、はせ、ヒトデの雑記サイトで `ERR_TUNNEL_CONNECTION_FAILED`。シェルからも接続トンネルのHTTP403が返った。環境側の制限であり、各サイトの閉鎖やサイト自身が返した403とは判断しない。権限を追加した実行でも同じ結果だった。

hitodeblogは、公開ページを証明書検証除外で読み取り、PC1440px・スマホ390pxの実画面とCSSを確認した。背景は生成り、カードや案内は暖色、同じキャラクターを使用。PCは本文＋プロフィール、スマホは入口カード2列・本文1列。確認した2幅で横はみ出しなし。実測値は `research.json` と `browser-verification.json` に保存。すべての画面・アクセシビリティ・速度の合格を意味しない。

残る4サイトの配色、フォント寸法、余白、画像の実際の明るさ、スマホの追従要素は未検証。想像で「青系」「2列」「古くさい」などと埋めていない。外部サイトのスクリーンショットや本文全文は公開リポジトリへ転載せず、私有作業領域に保持する。

## 今回の分析から決める運営方針

1. 書き手の立場は本人の固定軸で統一する。四人に似せるために経歴や感情を変えない。
2. 記事は「経験」「比較・解説」「必要な人へのサービス紹介」に役割を分ける。同じ記事で全部を長々と繰り返さない。
3. 経歴を少しずつ出しても、一記事だけで疑問に答える。結論を伏せて次の記事へ引っぱらない。
4. 体験を増やす質問はテーマごとに絞る。仕事内容・案件名・取引先などの開示を前提にしない。
5. 広告は読者が必要とする場面へつなぐ。全記事を独立や転職の申込みへ着地させない。
6. デザインの改修は今回実行しない。本人が気に入った現在の基盤を保ち、まず文章と回遊の設計に参考を使う。
