## 統合の仕組み

同梱の固定計画以外は対象にできない。認証付きPOSTで、統合先と元記事9本の所有権・公開状態・最新指紋、統合先の全見出しを照合してから有効化する。一般公開の投稿削除・任意転送のAPIは追加しない。

旧9URLは比較記事内の該当商品へ301。カテゴリー、検索、フィード、REST一覧、サイトマップ、クライアント記事一覧から旧記事を除外する。内部リンクも該当節へ直す。端末に保存した旧記事は比較記事へ引き継ぐ。管理画面と認証付き編集履歴では元の本文を保管する。

これは審査時だけ隠して後で戻す運用ではない。読者向けに比較記事へ恒久統合する。元投稿のID・本文・初回公開日・画像を削除しない。復旧時は管理者が `hsh_supplement_consolidation` オプションを無効化し、保存済み本文・履歴を基に統合先を戻せる。統合先が非公開または見出し不足なら転送しない。

## 再審査について

修正の公開と検証が終わってから、AdSenseのサイト詳細で「問題を修正しました」にチェックし、審査をリクエストする。管理画面への認証済み接続がない限り、申請済みとは報告しない。ads.txtの承認とサイト審査の合格は別。
