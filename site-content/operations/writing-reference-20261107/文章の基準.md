# 文章を直すときの基準

2026-11-07、ロケットニュース24の公開記事4本を本文まで読み、構成・段落・具体性の作り方を整理した。対象は納豆の食べ比べ、久しぶりの飲食店訪問、ChatGPTを使った食べ歩き、専用スプーンの使用比較。4本の観察をサイト全体・全執筆者の統一規則とは扱わない。

## 参考にすること

1. **入口に具体的なきっかけを置く。** なぜその物や出来事が気になったのかから始め、読者が何を読めるか示す。本人から聞いた事実がなければ動機や場面を作らない。
2. **疑問と、その答えを近づける。** 比較なら比べる条件、手順なら次にすることを示す。冒頭の問いを記事末尾まで放置しない。
3. **感想の前に対象を置く。** 「よかった」だけで終わらせず、何が好きなのか、何と違うのかを既存の事実で書く。未確認の触感・匂い・食べ方を足さない。
4. **一段落で話を進める。** 導入の言い換えを直後に繰り返さず、次の段落では理由・違い・注意点など新しい情報を渡す。短くするためだけにすべて一文ずつへ切らない。
5. **見出しはその先を予告する。** 対象や疑問を具体的に入れる。「特徴を確認」「公式案内とポイント」のような見出しが続く場合は、その節の内容に合わせる。
6. **話し言葉と説明をつなぐ。** 本人の「好き」「うちでは」「気がする」は残す。突然「〜の観点から検討する必要があります」と報告書調へ変えない。商品仕様の丁寧な説明とは役割を分ける。
7. **違いを示してから判断を述べる。** 共通点・違い・選ぶ条件を順に示す。一つの商品を褒め続けるだけにしない。
8. **結びは判断の材料にする。** 本人の好み、選ぶ条件、次に確認すべき公式情報を短く残す。「ぜひチェック」だけで終わらせない。
9. **文章を作っている事情を本文へ出さない。** 「詳しい香りの名前を足すより」のような執筆上の注意書きは内部基準へ戻し、読者には実際の感想を伝える。
10. **比較条件と限界を省かない。** 一回の体験を全製品・全利用者へ広げない。ただし同じ断りを各段落へ機械的に繰り返さない。

## 記事の種類による使い分け

体験談：本人が実際に話したきっかけ → 起きたこと・感じたこと → 好みや次の判断。実際の会話・行動・心理を作らない。

調べた商品紹介：選ぶときの疑問 → 公式情報で分かる具体的な違い → 条件や注意点 → 元の広告リンク。実物を見た・購入した・食べさせたという展開へ変えない。タイトルの【ご紹介】と広告表示を維持する。

手順解説：困る場面 → 先に見る箇所 → 手順と具体例 → 間違いを避ける確認。仕事で実際にその確認を毎回していたという経歴は作らない。

## 避けること

固有の決め台詞や比喩を写さない。記事の写真や本文を転載しない。過剰な「!?」「まさか」「衝撃」「〜してみた」を一律に付けない。ロケットニュースの名前や語勢を借りて、根拠のない体験記事にしない。価格・配合・症状・性能の根拠は参考メディアではなく対象商品の公式資料で確認する。

## 校正の流れ

①本人の事実と商品資料を確認 → ②読者の疑問を一文で決める → ③導入と直後の重複を読む → ④曖昧な語・急な文体変化・メタ説明を直す → ⑤元の数値・リンク・条件と照合 → ⑥声に出してつながりを読む。

`tools/editorial-quality.py` は執筆事情の露出と導入の重複候補を追加検出する。候補をすべて自動置換するものではない。今後の記事作成・改稿では、既存の編集基準とこの基準を併用する。

## 時期の自然な言い方

2026-11-10の本人指定：体験談の「今から2年前」「今から1年前」を、「2026年11月から2年弱前」のような不自然な基準日付き表現に変えない。本人の指定した自然な言い方を使い、公開日・更新日は記事の日付表示で管理する。

## 体験談に説明を足しすぎない

2026-11-10の本人指摘：「当時は約6,500円で買った」と書けば、続けて「今の販売価格ではありません」と断る必要はない。アルコール度数と刺激の因果を本文へ持ち込み、否定する説明も足さない。確認済みの感想を直接書き、執筆時の注意を読者向けの文章へ混ぜない。健康や治療、料金条件など、読者の判断に必要な注意は具体的な箇所に残す。
