# 他の成分をサイトから処理するための公開設定

現在の https://paperdesk-demo.onrender.com/ は無料の静的サイトです。そこにAPIキーを埋め込むことはしません。既存のPythonサーバーを別のWeb Serviceとして公開し、準備ができてから元のURLを案内先につなぎます。

## 実装と公開の区別

コードは成分入力、2000年以降のPubMed取得、PMID重複排除、初回判定、2回の再チェック、51分類のZIP、SQLiteへの再開記録に対応します。日本語名は確認済み別名表、英語名は入力した検索語を使います。未知の日本語名は英語名を求め、検索失敗をゼロ件成功とは扱いません。全文ではなくPubMedのタイトル・抄録を使うため、不明な判断は要確認にします。

公開先は未作成です。模擬APIのテスト成功は実論文での分類精度やOpenAI接続成功を意味しません。公開後に実接続の確認が必要です。

## 運営者の初回設定

1. Renderで既存の `scudetto0630-dotcom/blog` リポジトリから **New Blueprint Instance** を作成。
2. Branchは `main`、Blueprint Pathは **`paper-tool/render-live.yaml`**、名前は `paperdesk-live`。
3. 表示される有料Web Serviceと1GBディスクの料金を確認。これはOpenAI API料金とは別です。所有者の承認なしには作成しません。
4. `OPENAI_API_KEY` に自分のOpenAIプロジェクト用APIキーを登録。チャットやGitHubには貼らない。
5. `APP_ACCESS_PASSWORD` に12文字以上の共有パスワードを登録。利用者にはAPIキーではなくこのパスワードだけを渡す。ログインのユーザー名は `user`。
6. デプロイ完了後のURLで、認証、他成分のPubMed実取得、料金見積り、上限承認、実AI判定、2回の検証、ZIPを確認する。

本番用のモデルは `gpt-4.1-mini-2025-04-14`。入力$0.40 / 出力$1.60（各100万トークン）を設定例として記載しています。これはモデル公開時の料金に基づく値であり、2026年10月現在の料金を実接続で再確認できていません。運営者は公開前にOpenAIの最新料金・モデル利用可否を確認し、Renderの設定を更新してください。値が違うと費用見積りやアプリ内の上限計算も違ってきます。

初期のジョブ上限は$1.00です。論文取得後、100論文あたりとジョブ全体の概算を表示し、画面で上限を承認するまではAIを呼びません。上限に達したら停止し、進捗は保存します。1万論文の完了を$1で保証するものではありません。これはアプリが設定単価から計算する上限で、OpenAI側の実請求を保証する仕組みではありません。料金の改定、別アプリでの利用、応答不明の課金は別途確認が必要です。

## 元のURLから使う

新しいサーバーで実接続確認ができた後に行います。

- 元のRender静的サイトのEnvironmentに `PAPERDESK_LIVE_SITE_URL` を追加し、新しいWeb ServiceのHTTPSルートURLを設定。
- 元の静的サイトを再デプロイすると、新しいサーバー画面へ案内します。キーはこの設定に入れません。
- `https://paperdesk-demo.onrender.com/?provided=1` では元の提供資料版を引き続き開けます。元の製品・履歴はブラウザ内に残り、別URLのサーバーに自動移行しません。
- 切り替え前に元の製品一覧からバックアップを保存してください。サーバー版への自動インポートは今回追加していません。

問題がある場合は `PAPERDESK_LIVE_SITE_URL` を削除して元の静的サイトを再デプロイします。Web Serviceやディスクを削除する操作は行いません。

## サーバーと永続化

`render-live.yaml` はPythonのWeb Service、Starterプラン、1GB永続ディスクを指定します。料金はRenderの作成画面で確認してください。無料の静的サイトや、無料Web Serviceの一時ファイルでは、画面を閉じた後の継続処理と再起動後の保存を同じ条件では保証できません。

データベースは `/var/data/paperdesk.sqlite3`。単一プロセスとファイルロックで実行し、論文・ラウンドごとの判定・費用予約を保存します。サーバーの再起動後は未完了から再開します。API応答が失われ請求状態が不明になったリクエストは勝手に再送しません。運営者の確認が必要です。

OpenAI APIキーとRender管理権限はこのCodex環境にはありません。Codex側で実APIの動作確認まで行う場合は、環境の秘密情報に `OPENAI_API_KEY` を安全に登録し、API接続先へのアクセスを有効にしてください。Render側のEnvironmentへの登録とは別であり、Codexの秘密情報を保存しただけではRenderへ自動転送されません。
