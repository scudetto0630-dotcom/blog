# 設計と次段階の接続境界

## 現在

ブラウザはHTTP APIだけを通じて入力を保存し、デモジョブを作成します。判定処理や秘密情報をブラウザに持たせません。SQLiteとデモワーカーはサーバー側です。ブラウザの進捗確認は定期的なGETで、ブラウザの離脱によってジョブを停止しません。

現段階の工程は固定データと待ち時間によるデモであり、PubMed検索、成分解析、研究の採否判定、部位の意味解析、教師データ照合、独立検証は行っていません。第7工程も実ファイル生成ではなく、デモ結果の保存です。

### HTTP API

- GET `/api/config`: 工程と51分類。
- GET/POST `/api/products`: 製品一覧・登録。
- GET/PUT/DELETE `/api/products/{id}`: 取得・更新・削除。
- GET/POST `/api/jobs`: 履歴・デモ開始。
- GET `/api/jobs/{id}`: 進捗・結果。

JSON入力をフロントとサーバーの両方で検証。名前は120文字、成分は1〜5個・各120文字。Unicode正規化と大小文字・連続空白の整理で重複を検査します。同義語の自動特定は未実装です。

### データ

- products: ID、owner_id、製品名、成分配列、作成・更新日時。
- jobs: ID、owner_id、実行時点の入力スナップショット、状態、完了工程数、結果、エラー、作成・更新日時。
- paper（デモ結果内）: demo ID、is_demo、ingredient、PMID/DOI、title、abstract、initial_decision、checks[第1回、第2回]、final_decision。
- decision: 採用/除外/要確認、body_ids配列、ヒト試験判定、理由、evidence配列、engine_version。
- taxonomy_version: `user-51-v1`。分類名称や順序はご指定の一覧を保持。
- artifact: `not_implemented`、ダウンロードURLなし。

初回の判定は再チェックで上書きしません。最終結果は separate final_decision として保持。修正数は理由・分類等の変更があるサンプル件数です。

## PubMed・AIを追加する段階

追加するサービスをフロントから切り離します。

1. IngredientResolver: 学術名・同義語・検索式、解決根拠の保存。
2. PubMedClient: 2000年以降の論文取得、NCBIの利用条件・レート制限・再試行を管理。
3. PaperRepository: PMIDを一意キーとして重複排除、元の抄録・取得日時・検索式を保存。
4. Classifier: 成分の介入有無、採否、複数分類、ヒト試験、引用根拠を構造化して保存。
5. ReviewOne: 初回と分離した検証実行。介入条件、採否、部位、ヒト試験を検査。
6. ReviewTwo: 教師データ整合、分類漏れ、一貫性、欠落・重複、出力品質を検査。
7. Exporter: 製品/成分/51分類/ヒト試験効果あり/除外/要確認/修正履歴を生成し、全工程成功後にZIPを公開。

本番ジョブでは両レビューが完了しない限り最終成果物を生成しない制約を追加。モデル・プロンプト・教師データの版、根拠の箇所、実行日時を各判定・レビューへ記録します。「独立検証」を固定デモや同じ判定のコピーで代用しません。

EGCGの3ファイルは未提供です。次段階でPMIDの抽出と突合、手動ラベルの由来・相違点を保存し、学習用・評価用を分離します。教師データを学習に使うことと評価に使うことを混同しません。

## 長時間処理・多ユーザー

現在は1プロセス・1デモワーカー。DBパスのロックで同じDBへの二重ワーカー起動を防ぎます。各工程はDBへコミットし、再起動時に未完了から再開します。

本番エンジン追加時はPostgreSQLと専用ワーカーへ移行し、job_steps / papers / decisions / reviews / artifacts を独立テーブルへ展開します。claim/lease、heartbeat、試行回数、再試行日時、キャンセル、成分・論文単位のチェックポイントを追加します。公開サーバーは専用のWSGI/ASGIサーバーへ移行します。

owner_idは拡張のための境界で、現段階は `local` 固定です。ユーザー登録・セッション認証・CSRFトークン・権限・DBでのテナント分離を追加するまではユーザーごとの非公開領域があるとは扱いません。

## セキュリティ・データ保全

SQLはパラメータ化。画面の入力文字はHTMLエスケープ。API入力サイズ上限、同一オリジンの書き込み検査、CSP、非キャッシュ応答を設定。外部公開時は共有パスワード必須、TLSはホスティング側で終端。APIキー・学習ファイルは未使用で、フロントへ埋め込みません。

SQLiteのWALとトランザクションで更新を保持し、バックアップツールはSQLite backup APIを使います。DBが破損した場合は自動で削除・初期化せず、エラーを返します。保存失敗時も入力は画面に残します。ログへ認証ヘッダーや入力内容を出しません。

インターネット公開後の侵入試験、大規模負荷、ホスティングの再デプロイ・バックアップ復元は現段階では未検証です。

## 無料公開版への変更

現在の `render.yaml` は `runtime: static`。有料プラン、永続ディスク、共有パスワード、常駐サーバーの指定を除去しました。公開時に使うのはビルドされたHTML/CSS/JavaScriptと固定JSONだけです。

UIは `data-storage="browser"` の場合、HTTP APIではなく `BrowserStore.request` アダプターを使用します。IndexedDBのproducts/jobsストアへ保存し、失敗時は入力を保持。デモの進捗は画面の定期確認で進みます。閉じていた時間を処理時間として扱わず、再表示時に最後の工程から再開します。サーバーで長時間処理を継続する機能とは異なります。

JSONバックアップを提供。形式・件数・ID・入力・ステータス・工程番号を検証し、2ストアの1トランザクションで復元。同期例外時も明示的にabortし、clearだけがコミットされる事故を防ぎます。バックアップに含まれる外部URLやHTMLを信用せず、今回の固定デモ結果を入力から再構成します。

サーバー版は削除せず、次段階のエンジン接続用に保持しています。無料静的版はAPIキーを使用せず、端末間共有やサーバーでの独立処理を提供しません。
