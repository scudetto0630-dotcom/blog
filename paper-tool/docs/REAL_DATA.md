# 成分入力から使う提供資料版

入口は既存の製品名・最大5成分の入力画面です。資料アップロードを日常操作として要求しません。
既存の製品保存・編集・削除と旧デモ履歴を維持します。

EGCG（エピガロカテキンガレート、エピガロカテキン没食子酸）とカテキンに対応。
開始すると登録済みの提供資料から該当成分を取り出して、実際の論文一覧と人間版の分類を表示します。
両成分24,292 PMID、EGCG10,900、カテキン21,182、人間版102。未掲載は除外とみなしません。
51分類外の人間ラベルは勝手に別部位へ置換せず要確認。カテキン資料は参考で、人間の正解とは扱いません。

**これは新規検索・AI仕分けを稼働させた完成版ではありません。**
未対応成分を入力すると説明を表示し、架空の結果を出さず停止します。
提供資料の再整理と本番エンジンを混同しないでください。

## データと結果

提供された4ファイルを実際に解析した正規化資料を `app/static/resources/provided.json.gz` に組み込みました。
公開版ではこれらの論文メタデータと教師ラベルが配信されます。元ZIP/TXT、APIキーは配信しません。
再生成は `node tools/bundle_research.cjs <元TXT> <AI ZIP> <人間ZIP> <製品ZIP>`。
人間版の掲載、使用しないフォルダ、AI提案、製品参考資料の出典を分けて保持。
日付の降順で51部位のTXT、ヒト試験ファイル、要確認、判定差分JSON、説明をZIP出力します。
独立した科学的再チェックを実施したとは表示しません。

処理履歴と製品はこのブラウザ・URLのIndexedDBに保存。別端末へ共有されません。
旧製品バックアップは製品・旧デモ履歴を対象にし、新しい提供資料の履歴は含みません。

## 本番エンジンの実装状況

- `app/pubmed.py`: 2000年以降の検索、日付分割で10,000検索上限を回避、再試行、100件ごとの本文取得。
- `tools/fetch_pubmed.py`: SQLiteに取得キューと論文を保存。中断後に未取得だけ再開。
- `app/engine/decisions.py`: 人間教師例を添えた初回、初回を見ない第1検証、整合性の第2検証。人間とAIの分類差分を教師例に含め、51分類外の人間ラベルを勝手に置換しない。原文にない根拠引用を拒否。判定不一致は要確認。
- `app/engine/pipeline.py`: 判定ラウンドごとに永続化し、再開時に済んだラウンドを再実行しない。評価用PMIDを教師例から除外。
- `app/engine/ledger.py`: 承認・キー・モデル料金がないと停止。費用予約を原子的に上限チェック。応答不明時は自動で再課金しない。
- `app/engine/export.py`: 実判定結果の51分類、ヒト試験、要確認、除外、全レビュー記録のZIP。

これらは `PAPERDESK_RESEARCH_ENGINE=1` のサーバー版で本番ジョブAPI・入力・進捗・履歴・ZIP画面に接続済みです。無料の公開静的サイトには接続していません。永続バックエンドの公開先と管理者側のAI設定が必要です。

AI処理前に100論文の推定金額を表示。ジョブ上限を設定して明示的に承認するまで有料処理を開始しません。運営者の有料処理許可・AIキー・モデルと単価設定がない場合も停止。無料取得した論文と途中のレビューを保存し、再試行可能です。モデル、入力、教師版が同一の検証済み結果は再利用し、再利用した旨を記録します。
この環境からNCBIへの実接続は403で失敗。NCBI接続先の追加は環境ドラフトに保存済み、未公開。
有料APIを実行していません。分類精度は未測定で、模擬APIのテストを科学的評価と扱いません。`tools/evaluate_research.py` は保存された判定だけを評価用PMIDと比較します。判定がない場合は欠落を表示し、成功率を捏造しません。
教師102件は人間版掲載例で、未掲載を負例へ変換しません。採否精度を測るための明示的な負例は不足します。

## 操作テスト

`node tests/live-browser.cjs`: 実HTTPサーバーと模擬PubMed/AIで、承認待ち・再起動保持・履歴・ZIP・判定一覧と51部位フィルタを検証。外部API・仕分け精度の検証ではありません。
`node tests/input-research-browser.cjs`: アップロードなしの入力→実結果→ZIP、更新、履歴、入力再利用、別名重複、4幅を検証。
`node tests/research-browser.cjs`: 旧資料インポート機能の互換性確認。
`node tests/static-browser.cjs`: `--demo`ビルドで旧無料デモを回帰確認。
このテスト後は `python tools/build_static.py` で提供資料版へ戻してください。
